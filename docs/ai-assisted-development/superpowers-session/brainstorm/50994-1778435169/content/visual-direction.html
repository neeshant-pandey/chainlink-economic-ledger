What moves through Bitcoin?

Imagine you slide a $20 bill across a table. The bill itself doesn't change — only who holds it. Bitcoin works the same way, but the “bill” is a chain of digital signatures, and the table is a public ledger anyone can audit.

The unit of movement is called a transaction. It is the only thing Bitcoin actually stores. Blocks just bundle them.

The Bitcoin Transaction

A transaction is a signed message that consumes existing UTXOs and produces new ones. It is the smallest atomic unit the protocol commits to.

Structure

FieldBytesMeaning
version4Protocol version (1 or 2)
input_count1–9VarInt count of inputs
inputs[]variableEach input references prior UTXO + signature
output_count1–9VarInt count of outputs
outputs[]variableEach output is value + locking script
locktime4Earliest block / timestamp valid

Fee derivation

The fee is implicit: sum(inputs) − sum(outputs). There is no “fee” field on the wire.

Step 3 of 6 · Bitcoin transactions

Inputs are receipts.
Outputs are promises.

Forget “balances” for a moment. Bitcoin doesn't store balances. It only stores unspent outputs: little IOUs sitting on the ledger, each lockable to a specific key.

To spend, you point at one of those IOUs (input), prove you own the key (signature), and write a new IOU for someone else (output).

UTXO #a3 is now consumed. It will never appear again. The two new UTXOs (#d8 + the fee) are now spendable by their owners.
